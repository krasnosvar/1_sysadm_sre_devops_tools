## Токены и MCP

Вывод инструмента остаётся в истории и пересылается на каждом ходу.
В Claude Code определения MCP-инструментов по умолчанию откладываются
и подгружаются по требованию (tool search), но результаты вызовов
остаются в контексте. Что помогает:

- тяжёлую диагностику поручать [субагенту](1_setup/3_subagents_roles.md),
  чтобы в основной разговор вернулась короткая сводка;
- использовать фильтры CLI вместо сырых дампов, например
  `kubectl get pods -n prod --field-selector=status.phase!=Running`;
- сжимать контекст после больших диагностических шагов
  ([память и контекст](1_setup/8_memory_context.md));
- отключать неиспользуемые серверы.

Опыт экспериментов: маскирование старого вывода инструментов снижает
стоимость примерно вдвое без потери качества
([токены и стоимость](4_studies/8_tokens_cost.md)).

## Практика работы

1. Один шаг за раз: проверять каждое изменение на рабочих данных или
   тестах и только затем переходить дальше.
2. Вычисления и сверку отдавать коду, а не модели; после значимого
   изменения требовать тесты или проверки
   ([как ставить задачу](3_prompting/README.md)).
3. Обязательные параметры без тихих значений по умолчанию, например
   `${VAR:?сообщение}` в скриптах.
4. Правила проекта, решения и измеренные результаты хранить в
   версионируемых файлах (`AGENTS.md`, `CLAUDE.md`), только то, чего
   нет в коде ([инструкции](1_setup/1_instructions.md)).

Готовый промпт для выравнивания конфигураций нескольких агентов:
