# Claude Code: настройка и работа

Описан локальный CLI 2.1.325. Облако, Desktop, расширение
IDE и Agent SDK имеют отдельные способы запуска. Не считать изменение
локального JSON автоматически настройкой cloud-сессии.
[Общая политика](../../3_prompting/README.md) действует без копирования
полного справочника в каждую сессию.

## Инструкции и приоритет

Личные правила: `~/.claude/CLAUDE.md`. Настройки пользователя:
`~/.claude/settings.json`; общие проектные `.claude/settings.json`;
личные проектные `.claude/settings.local.json`. Для одного запуска
есть `--settings`. Приоритет JSON: managed, CLI settings, project local,
project shared, user. Для env и специальных ключей проверять отдельный
контракт; нельзя описать все случаи одним правилом «CLI всегда выше».

`CLAUDE.md` и память - контекст модели, не запрет исполнения.
Для проектных правил используется также `.claude/rules/`.
Проверить загруженные источники через `/status`, ошибки через
`claude doctor`. Содержимое инструкций и safety policy определяет
ваш проект; не заменяйте их общим примером.

https://code.claude.com/docs/en/settings
https://code.claude.com/docs/en/memory

## Лимиты и роли

Проблема: автоматические ветви работы и рекурсивное делегирование.
Предпосылка: CLI с поддержкой перечисленных env; concurrency доступен
с 2.1.217. Сохраните исходный JSON и объедините с ним
[фрагмент](examples/settings.json):
два одновременных Agent-запуска, глубина один, `ultracode=false`.
Сохраните существующие `permissions`, `autoMode` и `model`.
Не заменяйте настройки целиком.

Это не абсолютный предел всех процессов: `/subtask`, resume, workflows
и agent teams имеют оговорки. Ultracode исключён из этого лимита,
поэтому выключен в примере. Общее число запусков
контролируется политикой, а не этими двумя переменными.

Скопируйте нужные примеры из `examples/` в `.claude/agents/` проекта.
Для личной области используйте `~/.claude/agents/`. Сохраните оригинал
при совпадении имени. Начните с одной роли; остальные необязательны.

| Пример | Куда поместить |
| --- | --- |
| researcher.md | .claude/agents/researcher.md |
| worker.md | .claude/agents/worker.md |
| reviewer.md | .claude/agents/reviewer.md |

Модели в подготовленных примерах:

| Имя | Модель / effort | Результат |
| --- | --- | --- |
| researcher | sonnet / medium | Источники и ответ |
| worker | sonnet / medium | Ограниченная реализация |
| reviewer | opus / high | Существенные риски diff |

Поля `model` и `effort` принадлежат frontmatter, не Codex TOML.
Модели здесь aliases: конкретная версия может меняться. Роли не имеют
Agent в списке tools; researcher также не имеет Bash/Edit/Write.
Reviewer имеет Bash для проверок, поэтому его read-only поведение
не является полноценной изоляцией от файловых изменений.

https://code.claude.com/docs/en/sub-agents

Сценарий исследования, текст для чата:

```text
Поручи researcher найти caller указанного обработчика.
Дай точный путь и известный симптом. Нужны путь:строка и цепочка вызова.
Не читать всю историю и не создавать других агентов.
```

Для двух независимых частей назначить `worker` разным файлам;
для значимого изменения дать `reviewer` diff и уже пройденные тесты.
Небольшую правку делает основной агент. Не выбирать команду через
`claude agents` для определения custom roles: в 2.1.325 эта команда
управляет фоновыми сессиями; пользовательские определения лежат в файлах.

## Модель, effort и восстановление

`/model` показывает доступные варианты. Пример выбора для одного запуска:

```bash
claude --model sonnet --effort medium
```

Для проваленной проверки сохранить вывод и назначить более сильный доступный
вариант, например reviewer на `opus/high`. CLI принимает
low/medium/high/xhigh/max, но поддержка зависит от модели. Не переносить `max` в
persisted `effortLevel`: документация этого поля его не принимает. Глобальный
effort не требуется менять ради роли. Переключение модели может повторно
загрузить большой контекст; не переключать её ради каждого мелкого шага.

https://code.claude.com/docs/en/model-config

`claude --continue` продолжает недавнюю сессию каталога;
`claude --resume` выбирает сохранённую. Новый клиент получает handoff.
После паузы проверить актуальность файлов/среды, а не верить памяти
о деплое. `/compact` полезен для сокращения беседы, но не заменяет
явно сохранённые решения, проверки и следующий шаг.

## Расширения и измерения

Skills в `.claude/skills/` и `~/.claude/skills/` хранят процессы;
MCP добавляет внешние инструменты; plugins могут включать и hooks.
Hook исполняется по событию и может запускать команду вне рассуждения
модели. Доверять только проверенному обработчику, понимать его доступ
и иметь возможность отключения. Не добавлять автоматический полный
тест на каждое событие Stop без необходимости.

https://code.claude.com/docs/en/skills
https://code.claude.com/docs/en/mcp
https://code.claude.com/docs/en/hooks

`/cost` и `/usage` отвечают на разные вопросы. Денежный показатель API
не равен доле подписочного лимита. Из `-p` JSON сохранять доступные
метрики и modelUsage, не публикуя transcript с рабочими данными.
`--max-turns` ограничивает печатный запуск, но маленькое число может
остановить задачу до проверки. Это предохранитель теста, не доказательство
качественного завершения. Не меняйте платёжные настройки ради
воспроизведения примера.

https://code.claude.com/docs/en/costs

## Проверка, типичные ошибки и откат

Проверить JSON и YAML frontmatter, затем `claude doctor` и новый чат. Одним
вызовом установленного исследователя проверьте запрет чужого доступа и
отсутствие доказательства продового деплоя при зелёном CI.

При отсутствии роли проверить уникальное имя и `.claude/agents/`.
При неожиданном поведении лимита проверить ultracode и тип запуска.
Не исправлять отказ модели отключением permissions. Восстановить файлы
из резервной копии и начать новую сессию. При удалении примера не удалять
соседние существующие роли и настройки.
