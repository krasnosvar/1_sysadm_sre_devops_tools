# Поддержка базы и подготовка публикации

## Что входит в базу

Общие руководства, переносимые примеры, первичные исследования и
обезличенные результаты проверок. Внутренние инвентаризации, журналы
переноса, задачи компаний, персональные конфиги и полные transcripts
хранятся отдельно и не включаются в публикуемый каталог.

README служит короткой навигацией. Общий принцип описывается один раз;
раздел инструмента раскрывает только его реализацию и ограничения.
Не подключайте всю базу к постоянному контексту каждого агента.

## Добавить исследование

1. Откройте первоисточник и нужную часть авторского кода.
2. Запишите авторов, тип, публикацию, версию/обновление и дату проверки.
   Отдельно отметьте abstract-only и недоступные разделы.
3. Объясните механизм, условия сравнения, результаты, ограничения и стоимость
   подхода.
4. Свяжите вывод с руководством, примером и статусом проверки.
5. Проверьте release/commit и поддержку репозитория. Не заменяйте
   неизвестный timestamp датой своего чтения.

## Обновить руководство

После изменения клиента, схемы или model aliases проверьте локальную
help и официальную документацию. Укажите поддерживаемую среду и версию.
Проверьте синтаксис примера, загрузку и один содержательный кейс.
Разделяйте рекомендацию, подготовленный пример и наблюдавшийся результат.
Фраза «проверено» должна объяснять, что именно и в каких условиях.

Новые исследования добавляйте в [4_studies](4_studies/README.md):
постановка, результат с цифрами, ограничения, ссылка. Не переносите
benchmark-проценты на подписку.

## Проверить базу

Предпосылки: Python 3.11+, Bash и PyYAML. Команды выполняются из каталога
`2_agents`. Установленные агентные клиенты и доступ к модели не нужны.
При отсутствии PyYAML установите его в отдельное Python-окружение
по правилам своего проекта, не меняя системный Python.

```bash
python check_docs.py --self-test
```

Проверяются относительные ссылки внутри базы, JSON/TOML/YAML примеров,
парность блоков Markdown и Bash-синтаксис. Команды из документации
не исполняются. Проверка не заменяет полный secret scan и проверку
внешних ссылок. Значимые внешние источники открывайте адресно.

Перед публикацией дополнительно проверьте:

- отсутствие имён сотрудников, адресов, внутренних доменов и repo URL;
- отсутствие account/cluster/session IDs, токенов и логов авторизации;
- отсутствие абсолютных путей к личной машине и внешних локальных ссылок;
- отсутствие зависимости скриптов от пользовательских конфигов;
- отсутствие утверждения, что пример уже применён у читателя;
- соответствие имён ролей в примерах, командах и руководствах.

## Изменения и откат

Используйте обычный review-процесс своего репозитория. До изменения
конфигурации сохраните оригинальный файл отдельно от публичной базы.
Вносите только нужные ключи, сохраняя существующие разрешения и MCP.
При откате верните этот файл и начните новую сессию клиента.
Не публикуйте резервные копии личных настроек.

Для документации сохраняйте изменения в Git с учётом правил проекта.
В каталоге без Git сначала сделайте резервную копию вне публикуемого
дерева. Не включайте в универсальное руководство путь к конкретной
резервной копии автора. Публикация в удалённый репозиторий является
отдельным действием, а не частью проверки Markdown.

## Структура и пересмотр

Разделы: `1_setup` (приёмы), `2_tools` (клиенты), `3_prompting`,
`4_studies`, `5_sources`, `6_china_ecosystem`, `7_prompts`.
Факты о версиях, моделях и ценах датируйте и пересматривайте не
реже раза в квартал, китайский блок раз в месяц. Пометку «не проверено»
снимайте только после открытия первоисточника. Валидатор разрешает
ссылки на соседние файлы каталога `4_ai_tools` (соседние папки).
