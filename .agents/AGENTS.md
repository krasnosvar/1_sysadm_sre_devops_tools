# AGENTS.md — SysAdmin / SRE / DevOps tools

Операционный репозиторий: «как выполнить задачу» — команды, bootstrap
рабочих станций, поддерживаемые утилиты и карта AI-инструментов. Это не
база знаний: теория, уроки, упражнения и подборки ссылок на курсы живут в
отдельных репозиториях (см. «Related Repositories» в корневом
`README.md`). Контент репозитория — на английском.

## Структура (не добавлять новых верхнеуровневых каталогов без запроса)

| Каталог | Что лежит | Чего там быть не должно |
| --- | --- | --- |
| `1_linux/1_shell_bash_commands/` | Справочник команд по разделам `0_`–`14_` | Готовые проекты, конфиги целиком, теория |
| `1_linux/3_scripts_bash_python/` | Поддерживаемые утилиты с `--help`, кодами выхода, безопасными дефолтами и проверкой в CI | Учебные упражнения, разовые скрипты |
| `1_linux/fedora/`, `ubuntu/`, `2_win/`, `3_macos/` | Bootstrap-скрипты ОС | Справочники команд |
| `4_ai_tools/` | Карта AI-инструментов | Скрипты установки (они в `1_linux/fedora/5_ai_tools.sh`, на него только ссылаться) |

## Справочник команд (`1_shell_bash_commands/`)

- Команды по сервису/инструменту — один файл `<tool>.sh` в подходящем
  разделе. Каталог-подраздел только если файлов по теме несколько
  (`13_db_storage/postgresql/`).
- Новый раздел — следующий номер (`15_...`), при этом обновить дерево и
  нумерованный список в `1_shell_bash_commands/README.md`.
- `.sh` здесь — фрагменты для копирования, не исполняемые программы;
  `bash -n` к ним не применяется.
- Не возвращать каталог `2_services/` и аналоги-свалки: примеры
  Dockerfile/compose/Terraform/k8s-манифестов, ролей Ansible, конфиги
  конкретных рабочих мест, копии man-страниц сюда не кладутся.
  Исключение — пример, которого нет больше нигде и который пользователь
  явно решил оставить (`11_virt_iac_cloud/vmware/`).
- Если есть учебная лаба в базе знаний (например, Terraform + libvirt в
  `5_devops_sre_knowledgebase/0_lab_setup/`), здесь только ссылка на неё.

## Граница с базами знаний

- Теория, курсы, сертификации, книги, roadmap'ы, личные конспекты →
  соответствующая `*_knowledgebase` (Go → `3_go`, Python → `4_python`,
  DevOps/SRE/облака/сертификации → `5_devops`, AI/ML → `6_ai`).
- Каталогов вроде `what_to_learn/` здесь не заводить.
- Перед удалением материала — проверить, что он уже покрыт в базе знаний
  (по теме, а не только по тексту); непокрытое — сначала перенести или
  спросить пользователя.
- Шпаргалки (`CHEATSHEET.md`) в базах знаний запрещены; команды для
  копирования живут здесь, в `1_shell_bash_commands/`.

## При перемещении/удалении файлов

- Использовать `git mv` / `git rm`, чтобы сохранить историю.
- Искать старые пути по всему репозиторию и в соседних репозиториях
  (`../5_devops_sre_knowledgebase/*/README.md` ссылается сюда), а также
  в `.gitignore` и `.github/workflows/validate.yml`.
- Не коммитить без явной команды пользователя.
